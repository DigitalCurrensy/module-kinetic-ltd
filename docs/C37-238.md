# IEEE C37.238 vs Phasepin

Module Kinetic Ltd. Phasepin does not implement this profile. The switch fabric does.

## Profile

IEEE C37.238-2017 is the Power Profile for IEEE 1588-2008 in substations.
It extends IEC/IEEE 61850-9-3:2016 with continuous time-inaccuracy monitoring
and a C37.238 TLV (grandmaster ID + network time inaccuracy).
C37.238a-2023 adds a leap-second event TLV.
2011 numbers still quoted in the field:

```
logAnnounceInterval        = 0     # 1 s
logSyncInterval            = 0     # 1 s
logMinPdelayReqInterval    = 0     # 1 s, peer-delay
announceReceiptTimeout     = 2     # preferred GM
                           = 3     # other GM-capable
delay mechanism            = P2P
```

## BMCA timeout tuning

```
T_lost = announceReceiptTimeout × 2^{logAnnounceInterval}   seconds
```

C37 preferred GM: 2 × 1 s = 2 s.
C37 other / 1588 default-ish: 3 × 1 s = 3 s.
Shorter T_lost → faster GM swap, more false loss on a congested Announce path.
Longer T_lost → slower swap, more time on the dying GM.

That timer elects a master. It does not measure `|ptp_offset_ns|`.

Live Phasepin gate is `PTP_GOOD_NS = 1_000_000` (1 ms) on an already-measured
offset. Power-profile target in a substation fabric is sub-microsecond —
about 1000× tighter. A BMCA failover that finishes in 2 s with |offset| ≥ 1 ms
is holdover or `gps_peer` here, not a PTP pin.

Holdover 4 h is a CSAC aging budget. It is not an Announce timeout.
