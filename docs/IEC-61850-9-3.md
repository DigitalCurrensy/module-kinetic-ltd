# IEC/IEEE 61850-9-3 vs C37.238 TLV vs Phasepin

The standard is IEC/IEEE 61850-9-3:2016.
Live `pin_time` does not parse Announce or any TLV.

## Two documents, one fabric

| | IEC/IEEE 61850-9-3:2016 | IEEE C37.238-2017 |
|---|-------------------------|-------------------|
| Role | Performance floor for utility PTP | Extension over 9-3 |
| Transport | Ethernet L2, P2P delay | Same |
| BMCA | Default 1588 | Default 1588 |
| Target | < 1 µs after 15 TCs or 3 BCs | Same floor + path inaccuracy |
| GM inaccuracy | 250 ns | 200 ns (2011) / 250 ns (aligned 2017) |
| TC | 50 ns | 50 ns |
| BC | 200 ns | 200 ns |
| GM holdover-in-spec | 250 ns for 5 s (9-3) | 2 µs for 5 s (2011 quote) |
| Inaccuracy TLV | Not required | Mandatory IEEE_C37_238 TLV |
| Short GM ID | 64-bit Announce only | + 16-bit user GM ID in TLV |
| IRIG-B / ATOI | — | Local time + Alternate Time Offset |

9-3 slaves can sync to a 2017 GM. A 2017 slave talking to a 9-3 GM gets time, not the TLV extras.

## C37.238 time-inaccuracy TLV

2011 v1 fields on Announce:
- GrandmasterID (short; 2011 range limited, MSB reserved 0)
- GrandmasterTimeInaccuracy (ns, worst-case GM vs traceable time)
- NetworkTimeInaccuracy (ns, accumulated on the path; GM emits 0)

2017 v2 (not wire-compatible with v1):
- grandmasterID widened to full 16-bit, use optional
- source time inaccuracy introduced
- totalTimeInaccuracy is the cumulative field (GM + source + each TC/BC adds its own)
- Compatibility note: a 2011-minded slave may still sum (reserved=0 + totalTimeInaccuracy)

Each BC/TC **adds** its contribution and forwards. Nokia/field default: 100 ns GM, 50 ns BC, overridable.
C37.238a-2023 adds a leap-second event TLV. That is calendar, not offset.

clockAccuracy in the 1588 header is a coarse enum. The TLV is the fine worst-case estimate C37.118 synchrophasors actually consume.

## Live Phasepin

```
PTP_GOOD_NS = 1_000_000   # 1 ms operations gate on ptp_offset_ns
```

A 9-3 / C37 fabric that stays inside 1 µs totalTimeInaccuracy still stamps `ptp` here.
Phasepin does not refuse on TLV. It does not store grandmasterID.
Putting announced inaccuracy on the pin is a later carried field, not this file.
